## Краткое описание результата

Адаптивная административная панель на Bootstrap 5:

- верхняя навигация (navbar) с мобильным collapse;
- 4 карточки показателей из `dashboard.json`;
- таблица последних операций (responsive);
- модальное окно с формой добавления новой операции;
- offcanvas со списком уведомлений из `notifications.json`;
- accordion с дополнительной информацией;
- toast-уведомления;
- собственный JavaScript (загрузка данных, валидация, 4 обработчика событий, программный доступ к Toast и Modal).

## Как запустить

1. Клонируйте репозиторий (или скачайте архив).
2. Откройте папку проекта в VS Code / Cursor.
3. Запустите **Live Server** (или любой локальный HTTP-сервер), потому что `fetch` JSON не работает по протоколу `file://`.
   - Расширение Live Server → «Go Live»
   - Или из терминала: `npx serve .` / `python -m http.server 5500`
4. Откройте в браузере адрес, который покажет сервер (обычно `http://127.0.0.1:5500`).
5. Откройте DevTools (F12) → вкладка Console — ошибок быть не должно.

> Без локального сервера JSON-файлы не загрузятся из-за политики CORS браузера.

## Что делает Bootstrap JavaScript, а что — app.js

### Bootstrap JavaScript (подключён через `bootstrap.bundle.min.js`)
- Открытие / закрытие **modal** по `data-bs-toggle="modal"`
- Работа **offcanvas** (кнопка «Уведомления»)
- **Accordion** (collapse)
- **Navbar collapse** на мобильной ширине
- **Toast** (показ / скрытие)

### Собственный app.js
- Загрузка `dashboard.json` и `notifications.json` через `fetch`
- Рендер карточек метрик и таблицы
- Клиентская валидация поля «Название операции» (`is-valid` / `is-invalid`)
- Обработчик кнопки «Сохранить» (добавление строки + toast)
- Обработчик кнопки «Обновить данные»
- Обработчик кнопки «Сменить тему текста»
- Программный доступ к Toast и Modal через `bootstrap.Toast.getOrCreateInstance` и `bootstrap.Modal.getOrCreateInstance`

## Сценарий проверки

1. Открыть страницу → увидеть 4 карточки и таблицу (данные из JSON).
2. Нажать «Уведомления» → открывается offcanvas со списком из `notifications.json`.
3. Нажать «Добавить операцию» → открывается modal.
4. Оставить поле пустым / ввести 1–2 символа → появляется красная рамка `is-invalid`.
5. Ввести корректное название → зелёная рамка, нажать «Сохранить» → строка появляется в таблице, modal закрывается, toast показывает «Изменения сохранены».
6. Нажать «Обновить данные» → данные перезагружаются, toast подтверждает.
7. Изменить ширину окна до 375 px → navbar сворачивается, карточки становятся в одну колонку, таблица прокручивается горизонтально внутри контейнера.
8. Console без ошибок.

## Контрольные ответы (для защиты)

1. **Входные данные** — файлы `data/dashboard.json` (metrics + rows) и `data/notifications.json`.
2. **Преобразование в интерфейс** — функции `renderMetrics()`, `renderTable()`, `renderNotifications()` в `js/app.js`.
3. **Ошибочное состояние** — валидация поля «Название операции»: пустое или < 3 символов → класс `is-invalid` + toast «Проверьте обязательные поля».
4. **При росте проекта** — вынести рендер в отдельные модули, добавить роутинг, хранить состояние в store, подключить backend API.
5. **После клонирования** — `git clone …` → Live Server → открыть index.html.
6. **Семантика vs визуал** — теги `<nav>`, `<main>`, `<section>` дают смысл структуре; Bootstrap-классы и CSS отвечают только за внешний вид.
7. **Браузерный JS vs Bootstrap JS** — браузерный (наш app.js) управляет данными и логикой; Bootstrap JS управляет поведением готовых UI-компонентов (открытие modal, collapse и т.д.).
